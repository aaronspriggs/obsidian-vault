# Gluetun stuck exited — watchdog wins IP race for Gluetun's pinned 172.39.0.2, not namespace sharing

CORRECTED 2026-07-11 (original diagnosis on 2026-07-10 was wrong — see below): Gluetun needs a pinned static IP, 172.39.0.2, because other containers hardcode that address to reach NZBGet through the VPN. gluetun-watchdog runs as a normal servarrnetwork bridge container (NetworkMode=servarrnetwork, confirmed via docker inspect) with NO static IP of its own — it takes whatever the bridge's IPAM hands it dynamically. Whenever Gluetun isn't currently attached to the network (crashed, mid-recreate, stuck in Created state), Docker treats 172.39.0.2 as free. If gluetun-watchdog starts before Gluetun claims it, the watchdog can be handed that exact address, and Gluetun's own start/recreate then fails with 'address already in use.' This is NOT network namespace sharing (original theory was incorrect) — the watchdog only needs bridge-network reachability to Gluetun's control API on port 8000, not a shared namespace. Separately discovered: this stack has TWO divergent compose.yaml files — the documented one at /mnt/Big Boi/BIGBOI/servarr/compose.yaml is stale (still lists 'overseerr', missing gluetun-watchdog); the live file Dockhand actually manages is at /mnt/.ix-apps/app_mounts/dockhand/data/stacks/Big Boi/servarr/compose.yaml. Fix applied: recreated nzbget/prowlarr/gluetun-watchdog against the correct live compose file, then manually sequenced restart (stop all three, start Gluetun alone, confirm healthy, then start the other three together) rather than relying on `docker compose up`'s automatic dependency ordering, which does not safely sequence recreation of a container other services depend on via static IP. Verified stable 2026-07-11 — Gluetun holds .2, watchdog landed on .3, NZBGet/Prowlarr both clean. END-TO-END VALIDATED 2026-07-11: ran a real Interactive Search from Sonarr on a monitored missing episode, grab sent to NZBGet, confirmed actively downloading through the VPN. Full pipeline (Sonarr/Prowlarr/NZBGeek/NZBGet/Gluetun/Newshosting) confirmed working, not just containers up. Durable fix still open: pin gluetun-watchdog to a fixed non-.2 static IP in the compose file so start order can never cause this again.
