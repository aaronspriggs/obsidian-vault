# check.py --map lists a note's links; --health leads with open work

Aaron, 2026-10-23: asked whether session start is efficient now that the KB is local, and whether a graph layer (he'd seen Graphify) would help Claude drill down to the right notes. Graphify was ruled out for the vault: it parses code for free with tree-sitter, but runs markdown through the session's model, so it would spend tokens rebuilding a copy of relationships the vault already states exactly (required `system`, `project`, `runs_on`, `parent`, `superseded_by` links plus ~885 body links, all validated by `check.py`). The real cost was triage: 127 notes link to [[Home Assistant OS (VM)]] and a grep can't say which are open or current without opening them.

`.kb/check.py` now builds the link graph while it validates (no extra pass, no stored index, so it can't drift and nothing new has to be written when documenting):

- `--map "<note or part of its name>"` prints the note's status and summary line, then everything linked to or from it grouped as open projects (by priority, next_step capped at 120 chars), active runbooks, systems (marking ones hosted on it via `runs_on`), backlog names, and the 10 newest changes; done and deprecated notes are only counted. An ambiguous name lists the matches and exits 2. The Home Assistant map is ~5 KB (~1.3k tokens) in place of 127 backlinks.
- `--map` alone prints one line per non-deprecated System: category, status, IP, open/backlog/runbook counts and last change date (~2 KB).
- `--health` now starts with an **Open work** section (active then blocked, by priority, with next_step), which answers "where were we" without grepping projects. Full output is ~3 KB.

CLAUDE.md's session-start and token-budget rules now point at these ([commit](https://github.com/aaronspriggs/spriggs-homelab/commit/17cc7a9)).
