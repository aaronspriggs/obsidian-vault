All 13 hook records in the session transcripts since 2026-11-08 carry the preview; their outputs were 10,025 to 11,354 characters. The preview ended partway through open work, so the backlog list never reached context.
- **Long sessions are where the tokens go.** 68 transcripts hold 4,916 main-thread API requests that processed 1.16 billion tokens of context, 236k per request on average; 12 sessions account for 67%, and 74% was processed in requests above 200k. (A first count of 2.6 billion was wrong: it counted a request once per logged content block.) 28 sessions passed 200k of context, 11 passed 400k, and 5 of the 8 heaviest never shed context at all (the other three show one large drop each, 250k to 570k; an earlier "none ever compacted" was wrong), because current models run with a 1M window and Claude Code only compacts by default at about 967k ([model config, "Set the auto-compact window"](https://code.claude.com/docs/en/model-config)). 17 of 68 sessions ran past one calendar day. 98% of assistant turns were on Opus; the account is Claude Pro.
- **tier3-guard holds reads.** 15 holds on record (plus 3 hard denies): 9 were real automation deletes, 6 were read-only or unrelated Bash commands. The Bash check fires when a command writes anywhere and names a guarded path anywhere, and a `>` inside a quoted string counts as a write. Replayed over all 2,265 Bash commands in the transcripts, that rule matches 22; 16 of them are reads or writes to other files.
- **Docs drift.** STANDARDS.md "How Claude Code works the KB" predates the hook and `--map`; repo `README.md`, `claudecode-vm/README.md` and the `truenas-api` docstring still point at Notion; three System notes are over the 1,500-word limit.

- **Active project notes are the KB read cost.** Four are 2,500 to 7,200 words; STANDARDS has a size rule for System notes only. Backlog: 43 notes, 17 of them ideas.
- **Unversioned files on a disk with no backup:** `~/rack-artifact/`, `~/work-claude-brief.md`, `~/homelab-agent/mockup*.html`, `out/gpu-plan/`, `.archive/`, `settings.local.json.bak`, two project skills never invoked.

## Decisions

- **2026-11-15, step 1: trim the output rather than tell Claude to read the saved file.** The cap can't be raised, and the docs say Claude Code doesn't ask Claude to read the file, so an instruction to read it would depend on the same kind of remembering that failed with `--map`. Rejected: splitting the output across several hooks (each is capped separately, but it adds moving parts for a list that fits in one).
- **2026-11-15, step 1: what was cut and why.** The by-System list repeated every active and blocked project already in open work, and repeated a project under each System it names (6.2 KB). Systems to verify and untested runbooks (1 KB) are upkeep, not something a task needs at its start, so they are now a count. Kept at full length: open work with next steps, since that is what stops a missed project. Result: 6,924 characters, all 18 open projects and all 43 backlog titles.
- **2026-11-15, step 1: the limit is enforced in code, not by a note.** `check.py --session` shortens next steps, then drops them, to stay under 8,500 characters, and the hook cuts itself with a warning at 9,800. A new project can't silently push it over again.
- **2026-11-15, step 1: cost accepted.** A backlog project that names several Systems is listed only under the first. The point of the list is spotting an existing project by title before proposing one; `check.py --map "<System>"` still lists it under every System.
- **2026-11-15, step 2: cap the window instead of warning about it.** The first plan was a hook that tells Claude when context is large. Reading the docs showed the cause is a default, not a habit: nothing compacts before about 967k. A documented setting fixes that without a script, without depending on Claude passing a warning on, and without Aaron doing anything, so the hook was dropped. Replaying the transcripts with compaction at a given window (assuming 30k of context after each compaction and counting each compaction as one request at the full window) gives: 150k, 38% of the actual context tokens and 83 compactions; 200k, 47% and 55; 300k, 61% and 28; 400k, 72% and 17. Recommended: 200k, the size models ran at before 1M windows, about one compaction per heavy session. Cost: a compaction replaces earlier turns with a summary, so detail that was never written to the vault can be lost. That is what "write when it happens" is for, and the SessionStart hook already re-runs after a compaction. `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` would do much the same but as an environment switch for every model; the setting is the narrower change. Not decided until Aaron says yes.
- **2026-11-15, step 3: narrow the Bash rule rather than leave it.** A false hold only costs a retry, but three times on 2026-11-15 Claude answered one by using a different tool, and a guard that teaches working around it is worse than a narrower one. The Edit and Write tools, which is how Claude normally edits files, are still held on the exact path. New rule: a guarded path is held when a write verb precedes it in the same simple command, when it is a redirect target, or when an interpreter writes it (`open(PATH, 'w')`, `Path(PATH).write_text`). Checked three ways: 89 tests pass (15 new, including the real false holds); replayed over all 2,265 past Bash commands it holds 6 where the old rule held 22, and holds nothing the old rule let through; the 16 released commands were each read to confirm none wrote a guarded path. The first draft failed a test: the closing quote in `print('<x>')` was read as the start of a quoted redirect target, fixed by not letting a quoted target cross `;`, `&` or `|`.
- **2026-11-15, step 3: gaps accepted.** Not caught: a guarded path passed as a variable or function argument and written elsewhere in the command (a Python helper called as `sub("the rulebook", …)`). The old rule caught that only by accident, through the same looseness that held reads. Still held though harmless: copying a guarded file out (`cp ~/.claude/settings.json x`), and a script that quotes the guard's own patterns. The guard backs up Claude's judgment about Tier 3; it isn't a wall against a command written to dodge it.
- **2026-11-15, how much weight token spend should get (Aaron asked; he is open to a higher plan or working differently). Analysis, not yet decided.** The plan above leaned on the token budget because CLAUDE.md and memory say Pro plan, minimize. The evidence says that weighting has been costing accuracy in the wrong place. The Pi-hole miss (2026-11-08) happened at request 14 of a fresh session with 96k of context: a truncated grep and a skipped lookup, reading too little, not a long session. Reading is cheap next to carrying: the whole vault is about 230k tokens and the largest project note about 10k, against 236k of context re-sent on an average request. In the 12 heaviest sessions 67% of what entered context was tool output and 26% tool input; what Aaron typed and what Claude said is about 7%. So the waste is stale tool output carried for hundreds of requests, and the false economy is reading less of the KB. Revised recommendations: (1) window 300000 rather than 200000, since it halves the compactions (28 against 55 on replay) and keeps most of the saving (61% of actual against 47%); (2) a "Compact instructions" section in CLAUDE.md so a summary keeps Aaron's decisions and corrections, open questions and the state of the task in hand; (3) no Sonnet default, Aaron starts chats on Opus and the window applies to every model; (4) in step 4, replace "read sparingly" with "read what the task touches in full; don't carry stale context"; (5) the plan question turns on what Aaron already pays in usage credits (seven "monthly spend limit" messages on 2026-10-14 to 10-22, extra usage is enabled): at $80 a month or more on top of Pro, Max ($100, 5x Pro) costs less and removes the rationing.
- **2026-11-15, what compaction keeps (docs, [context window, "What survives compaction"](https://code.claude.com/docs/en/context-window)).** Kept: project-root CLAUDE.md and auto memory, both re-read from disk; up to five most recently modified files; skill descriptions; the output of SessionStart hooks that match `compact`, which the KB hook does. Summarized: the conversation, and "detailed instructions from early in the conversation may be lost". Steering: a "Compact instructions" section in CLAUDE.md, `/compact <focus>`, or a PreCompact hook whose stdout becomes instructions for the summary. Not documented: what happens to tool results and to tool schemas loaded through ToolSearch, so watch the first compaction.
- **2026-11-15, window size revisited: 400000 recommended.** Aaron asked whether 400k is safer for his heavy iteration sessions and said he has gone into usage credits only 3 times, so he stays on Pro. Nothing sets a window today (no `autoCompactWindow`, no per-model window, no environment variable), so sessions run on the 1M default and compact at about 967k. With spend rarely binding, the window's job is to stop runaway sessions, not to trim ordinary ones. At 400k only the 11 sessions of 68 that passed 400k would have compacted at all, 17 times in total and at most 3 times in one session, for 72% of the actual context tokens; 300k touches more sessions (28 compactions) for 61%. The cost of 400k over 300k is a larger summary request each time and a dearer first message when a big session is resumed cold. It can be lowered later from real experience, which is better than starting low and losing detail in a design session. Waits for Aaron's yes.
- **2026-11-15, step 3 live check: a write that adds nothing.** The planned check was `echo x >> ~/.claude/settings.json`. If the guard had missed it, that would have appended a stray line to the file that loads the guard and broken its JSON. Used `printf '' >> ~/.claude/settings.json` instead: the same redirect shape to the same path, so it tests the same rule, and a miss changes nothing. It was held (code af2f, left to expire; never retried).
